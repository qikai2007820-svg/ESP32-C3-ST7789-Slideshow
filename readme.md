### Preface
> This project is a digital photo frame based on the ESP32-C3 SuperMini development board, an ST7789 IPS 1.54-inch 240x240 display, and an SD card module. It was developed to create a 1:12 scale miniature diorama. This was my very first attempt at embedded development. From having zero background knowledge to completing the project—including component selection and production—the entire process took about 3 days with the help of Gemini. Since there is limited documentation available online regarding driving the ST7789 in RGB666 mode, I am documenting and sharing this project.

***Note: All code in this repository was generated by Gemini.***

Due to the limited resources of the ESP32-C3 (especially contiguous memory blocks), this project successfully drives the ST7789 screen by combining a "trade time for space" strategy (chunked reading) with a "trade space for speed" strategy (DMA transfers). By directly reading binary data (`.bin`), it pushes the ST7789 driver chip's 262K color expression capability to its absolute physical limits.

## Project Goals

- **Pushing Physical Color Limits**: Breaking through the typical RGB565 (16-bit color) limitation of standard graphics libraries to achieve the physical limits of **RGB666 (18-bit color, 262,144 colors)** display.
- **Lossless Image Slideshow**: By directly reading raw binary pixel streams, it eliminates image degradation caused by compression, resulting in a crisp and highly detailed digital photo frame.
- **High-Performance Refresh Rate**: Optimizing the data transmission path ensures smooth switching speeds even when playing high color depth images.

## Key Features

- **"Protocol Bypass" Direct Drive**: Abandoning the high-level functions of traditional graphics libraries, the project sends raw 24-bit (3-byte) pixel data directly to the driver chip via the SPI bus, achieving true 18-bit color display.
- **Split-Buffer DMA**: To address the ESP32-C3's memory fragmentation and lack of contiguous SRAM (about 147KB available), the screen is split into top and bottom halves (240x120) combined with asynchronous DMA transfers. This perfectly balances memory overhead and transmission speed.
- **PC-Side Preprocessing Mechanism**: Python scripts on the PC are used to handle RGB666 format conversion for BMP images, generating a `.bin` raw data stream without a file header. This completely eliminates the decoding burden on the microcontroller side.
- **Efficient SPI Bus Multiplexing**: On the pin-starved SuperMini development board, the screen and SD card share the SCK and MOSI lines. Two high-speed devices are precisely managed through independent Chip Select (CS) logic.

## Files Overview

### 1. `convert565.py`
A Python script with a graphical interface used to convert 240x240 resolution RGB888 BMP images into RGB565 format `.bin` binary streams. The script converts each pixel to 3 bytes and performs precise bitwise clipping, used mainly for testing and comparing RGB565 and RGB666.

### 2. `convert666.py`
**Recommended.** A Python script with a graphical interface used to convert 240x240 resolution RGB888 BMP images into 18-bit RGB666 format. It aligns color data through bit-shifting and is designed for ST7789 screen configurations that pursue the highest color reproduction and require 18-bit color depth support.

### 3. `esp.ino`
The core Arduino C++ firmware for the ESP32-C3, primarily responsible for the following tasks:
- Sequentially playing all bin file images in the root directory of the SD card.
- Searching for file names starting from `01.bin`, incrementing sequentially up to `99.bin`. Missing files in between are skipped.
- Initializing the ST7789 screen and SD card via the SPI bus.
- Using the DMA memory allocation mechanism to efficiently and quickly read the converted `.bin` files directly from the SD card.
- Implementing non-blocking continuous image reading and display, forming a relatively smooth digital photo frame slideshow.
- Adjusting screen backlight brightness via hardware PWM (default brightness is about 30%).
- Pin declarations within the program are referred to the wiring table above.

## How to use

1. **Use the Python script (`convert666.py`) to process images that meet the specifications (24-bit BMP format, 240x240).**
2. **Rename the generated `.bin` files to `01.bin`, `02.bin`... and place them in the root directory of the SD card.**
3. **Connect the circuit, flash the code, and power it on.**
